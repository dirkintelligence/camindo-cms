# camindo CMS – Manuals

camindo CMS manages all kinds of content – articles, products, addresses, images, appointments –
in freely definable ***content areas*** and outputs it via ***templates*** on one or several
websites. The manuals describe the range of functions of camindo CMS 9.

> Despite all care in keeping the manuals up to date, errors can creep in. No guarantee is given
> for the accuracy and completeness of the content.

## The manuals

### [Editors' manual](./editors/README.md)

For everyone who maintains content regularly: editors, authors, translators. Sign-in, the work
surface, searching, editing, multilingual content – and the tools for large amounts of data: batch
processing, CSV export for editing in Excel, and re-import.

### [Manual for administrators](./admins/README.md)

For everyone who sets up and looks after camindo CMS: installation, the concept of content areas,
input fields, websites (instances) and languages, user rights, media processing, structure export
and import, operation and maintenance.

### [Manual for template programmers](./templateprogrammers/README.md)

A textbook and reference for everyone who designs the output of the content: template programmers
and screen designers. Basics, template sets and the reference of all `(CMS:…)` commands.

Installed ***add-on components*** – modules, extensions, processors – come with their own manuals.
In the back end they appear in this overview under “Manuals of add-on components” and in the
selection of manuals.

For developing camindo CMS itself – your own modules, media processors, extensions and `(CMS:…)`
commands – there is a separate developer documentation (German and English). It does not belong to
these manuals; it lives in a separate repository.

## How the manuals are structured

The manuals serve as both a guide and a reference. The chapters build on one another and can be read
in order or printed. Cross-references lead to related topics, including across the manuals.

***Bold italic*** terms are listed in the keyword index. The index gives you all the relevant places
for a term.  
Plain **bold** only emphasizes.  
Names from the user interface, such as buttons, menu items and tabs, are set in quotation marks,
e.g. “Save”.

## Which functions are available to you?

Which functions you can use in the back end depends on the rights of your ***user group***. The
manuals deliberately describe the full range of functions, so that you also get to know functions
that are not (yet) enabled for you. If a function you would find helpful is missing, talk to your
administrator – they can adjust the rights of your user group.
